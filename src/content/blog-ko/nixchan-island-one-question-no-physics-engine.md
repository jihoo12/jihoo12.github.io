이제 이 사이트에 작은 게임이 하나 있어요. [/island](/nixchan/island/)에서 닉스쨩이 툰 스타일의 섬을 뛰어다녀요. 해변에서 바다로 헤엄쳐 나가고, 부두에서 낚시를 하고, 순무를 길러서 시장 가판대의 수달 페블에게 팔고, 옛 대장간에서 광석을 캐고, 바람 기둥을 타고 하늘에 떠 있는 섬들인 클라우드레스트까지 활공해 올라갈 수 있어요.

시작은 어느 저녁의 생각 하나였어요. [실험용 홈페이지](/nixchan/experimental/)의 3D 닉스쨩은 이미 걷고 뛸 줄 알았거든요. 그렇다면 갈 곳이 있으면 어떨까? 그 뒤로 하나씩 하나씩 자라났어요. 게임은 three.js 위의 TypeScript 약 7,000줄이고, 물리 엔진이 없어요. 이 글은 그게 어떻게 가능한지에 대한 이야기예요.

## 질문 하나

물리 엔진은 일반적인 문제를 풀어요. 어떤 모양이든 다른 어떤 모양과 부딪히고, 힘과 마찰과 충돌을 다뤄요. 제 섬에 필요한 건 훨씬 적어요. 닉스쨩은 언제나 무언가 위에 서 있거나, 무언가 안에서 헤엄치고 있거나, 무언가를 향해 떨어지고 있어요. 그래서 매 프레임 움직임이 묻는 건 하나뿐이에요.

> 여기서 닉스쨩이 딛고 설 것의 높이는 얼마일까?

섬은 **하이트필드**, 즉 가로세로 336칸짜리 높이 격자예요. 지형 메시도 같은 격자로 그려요. 어떤 지점의 땅 높이를 알려면 그 지점이 격자의 어느 삼각형에 있는지 찾아서 높이를 읽으면 돼요. 메시와 조회가 같은 삼각형을 쓰니까, 닉스쨩의 발은 언제나 눈에 보이는 풀밭 위에 정확히 닿아요.

높이는 함수 하나에서 나와요. 평평한 윗면이 해변을 지나 해저로 떨어지고, 언덕을 만드는 노이즈가 더해지고, 눈 덮인 봉우리를 만드는 혹이 하나 있어요.

```ts
export function mainHeight(x: number, z: number) {
	const d = Math.hypot(x, z) / R + fbm(x * 0.018 + 31, z * 0.018 - 7, 3) * 0.3;
	const base = 1.3 - 7.3 * smoothstep(0.52, 1.0, d);
	const inland = smoothstep(0.62, 0.36, d);
	const hills = (fbm(x * 0.03 + 5, z * 0.03 + 9, 4) * 0.5 + 0.5) * 6 * inland;
	const pd = Math.hypot(x - PEAK.x, z - PEAK.z);
	const peak = 16 * Math.exp(-(pd * pd) / 620) * smoothstep(0.75, 0.4, d);
	return base + hills + peak;
}
```

중심에서의 거리에 노이즈를 더해서 해안선을 안팎으로 밀어요. 그래서 섬이 동그라미가 되지 않아요.

## 모든 게 땅이에요

하이트필드는 시작일 뿐이에요. 닉스쨩이 딛고 설 수 있는 건 전부 같은 답에 합쳐져요. `groundAt`은 다음 중 가장 높은 걸 돌려줘요.

- 지형
- 부두의 갑판
- 바위 꼭대기 (원 위에 얹은 돔으로 다뤄요)
- 뛰어올라 설 수 있는 받침대의 평평한 윗면
- 그리고 하늘섬의 풀밭 (닉스쨩이 그 위에 있을 만큼 높이 있을 때만)

```ts
export function groundAt(x: number, z: number, y?: number) {
	let g = Math.max(terrainAt(x, z), deckAt(x, z));
	if (y !== undefined) g = Math.max(g, skyGround(x, z, y));
	for (const f of nearby(x, z)) {
		// 바위는 돔, 받침대는 패드
	}
	return g;
}
```

바위와 나무는 4미터짜리 칸으로 나뉜 격자에 들어 있어서, 매 프레임 전부가 아니라 근처의 몇 개만 살펴봐요.

모든 게 "땅"이 되면, 모든 움직임은 그 높이와 닉스쨩 자신의 높이를 비교하는 일이 돼요.

- **걷기**: 새 지점의 땅이 50센티미터(와 걸음 길이에 따른 약간)보다 더 높지만 않으면 걸어갈 수 있어요. 그래서 비탈은 그냥 오르지만 절벽에서는 멈춰요.
- **떨어지기**: 땅이 발밑으로 0.6미터보다 더 내려가면 가장자리에서 발을 뗀 거예요. 착지할 때까지 중력이 이어받아요.
- **헤엄치기**: 해저가 −1.35미터보다 깊어지면 헤엄치기 시작하고, −1.2미터보다 얕아지면 다시 발이 닿아요. 두 숫자 사이의 틈 덕분에 물가에서 걷기와 헤엄치기 사이를 깜빡이며 오가지 않아요.
- **활공하기**: 공중에서 한 번 더 점프하면 글라이더가 펼쳐져요. 천천히 가라앉다가 땅이 올라와 닿는 곳에서만 내려앉아요.

나무만은 땅이 아니에요. 줄기는 닉스쨩을 밀어내는 원이에요. 밀려날 때 줄기 쪽으로 향하던 속도 성분을 없애서, 줄기에 부딪혀 덜덜 떨지 않고 미끄러지듯 돌아가요. 공중에서는 나뭇잎이 공 모양이 되어서, 그 둘레로 활공해 돌아가요.

움직임이 막히면 x 방향만, 그다음 z 방향만 따로 움직여 봐요. 이 작은 요령 하나 덕분에 절벽에 달라붙지 않고 절벽을 따라 미끄러져요.

## 땅의 높이가 내 높이에 따라 달라질 때

하이트필드는 한 지점에 높이가 하나뿐인데, 클라우드레스트가 그걸 깨뜨렸어요. 커다란 하늘섬은 깊이 50미터짜리 바위 덩어리를 매단 채 해안 위에 떠 있어요. 그 아래에서는 같은 (x, z)에 딛고 설 곳이 두 개예요. 저 아래의 해변과 저 위의 풀밭이요.

해결책은 질문에 인자를 하나 더 받게 하는 거였어요. 닉스쨩이 얼마나 높이 있는지요. `skyGround(x, z, y)`는 닉스쨩이 하늘섬의 풀밭 높이이거나 그보다 높을 때만 그 풀밭을 돌려줘요. 그래서 위에 있을 때는 풀밭이 있고, 아래 해변에 있을 때는 없어요. 짝꿍인 `skyCeiling`은 아래에 있는 사람에게 바위의 밑면을 돌려줘서, 밑에서 섬을 뚫고 활공해 올라가지 못하게 해요.

하늘섬 위의 것들도 똑같이 동작해요. 클라우드레스트의 나무에는 그 나무가 서 있는 높이인 `floor`가 있고, 같은 높이에 올라온 사람에게만 존재해요. 그렇지 않으면 해변의 닉스쨩이 50미터 머리 위에 있는 나무줄기에 부딪힐 거예요.

그곳까지 올라가는 방법은 **윈드스파우트**예요. 언덕 비탈에 있는 바람 기둥이에요. `windLift(x, z, y)`는 바람이 글라이더를 얼마나 빨리 들어 올리는지 돌려줘요. 기둥 한가운데서 가장 세고, 꼭대기에서 잦아들어서 섬 가장자리 바로 위에서 수평으로 빠져나오게 돼요. 이것도 결국 위치에 대한 함수 하나예요.

## 나머지 조각들

나머지도 모두 몇 가지 같은 패턴으로 만들어져 있어요.

**E 키가 하는 일.** 섬에서 닉스쨩이 무언가 할 수 있는 건 모두 "제안 소스"를 등록해요. 매 프레임 할 말이 있는 첫 번째 소스가 이겨요. 그 문구가 안내창에 뜨고, E를 누르면 실행돼요. 낚싯대, 텃밭, 페블, 모루, 하늘 상자는 서로를 몰라요. 새로운 할 거리를 더하는 건 호출 한 번이에요.

```ts
interactions.add(() => (nearChest() ? { label: 'Open the chest', go: openChest } : null));
```

**저장.** 섬은 가방, 텃밭, 물고기 도감, 지도, 대장간을 `localStorage`에 기억해요. 모든 키는 `save.ts` 파일 하나에 모여 있어요. 섬이 커져서 예전 지도가 맞지 않게 됐을 때는 키 하나를 `island-map-v2`로 바꾸는 것으로 충분했어요. 읽기는 절대 예외를 던지지 않고, 저장된 값은 쓰기 전에 모양을 확인해요. 예전 버전에서 왔거나 누가 손으로 고쳤을 수도 있으니까요.

**모델.** 물고기, 텃밭, 페블, 하늘 유적, 대장간은 Blender로 만들었지만 손으로 만든 건 아니에요. 하나하나가 `tools/`에 있는 파이썬 스크립트로, 화면 없이 실행해서 만들어져요.

```sh
nix develop .#blender -c blender -b -P tools/island-otter/build.py -- otter.glb
```

스크립트가 three.js의 좌표계와 미터 단위로 모델링해서, 모델을 손볼 필요 없이 바로 장면에 넣을 수 있어요. 재질에는 단색만 들어 있고, 페이지가 이걸 3단계 음영 램프를 쓰는 툰 재질로 바꿔요. 그래서 섬의 모든 게 같은 느낌을 가져요. 그리고 스크립트이기 때문에 모델도 다른 코드처럼 고치고 다시 빌드할 수 있어요.

**아이콘.** 가방과 시장에 보이는 물고기나 순무 그림은 이미지 파일이 아니에요. 게임이 각 3D 모델을 화면 밖 렌더 타깃에 한 번 그려서 그 결과를 이미지로 간직해요.

## 처음의 나에게 해 주고 싶은 말

일반적인 해법을 찾기 전에, 게임이 실제로 묻는 질문이 뭔지부터 정하세요. 섬 위의 캐릭터에게 그 질문은 "여기 땅이 얼마나 높지?"였고, 헤엄치기도, 기어오르기도, 활공도, 심지어 떠 있는 섬까지도 그 질문의 답으로 들어맞았어요. 섬이 딱 한 번 맞지 않았을 때도, 답은 질문을 바꾸는 게 아니라 질문에 인자를 하나 더하는 거였어요.

물론 한계도 있어요. 닉스쨩을 밀어내는 건 없고, 굴러가는 것도 없고, 움직이는 두 물체가 부딪히는 일도 없어요. 이 섬에는 그걸로 충분해요.

[닉스쨩을 만나러 가 보세요](/nixchan/island/). 컴퓨터와 휴대폰 모두에서 되고, 가방과 텃밭, 찾아낸 장소들을 기억해요.
