저는 손으로 그린 것 같은 화이트보드를 좋아해요. 삐뚤빼뚤한 사각형은 "이건 초안이니까 얼마든지 반박해도 돼"라는 느낌을 주는데, 반듯한 사각형은 그렇지 않거든요. 그러면서도 지저분한 걸 깔끔하게 만들어 주는 도구들, 그러니까 스마트 가이드나 스냅, 정렬과 분배도 좋아해요. 그리고 이 두 가지를 다른 사람들과 같은 보드 위에서 동시에 쓰고 싶었어요.

[**Inkboard**](https://github.com/jihoo12/board)가 바로 그런 보드예요. 무한 캔버스 위에 거친 도형, 도형에 붙는 화살표, 펜으로 그린 선, 스티키 노트, 이미지, 프레임, LaTeX 수식을 그릴 수 있어요. 링크를 가진 사람은 모든 변경을 바로바로 보고, 서로의 커서와 선택 영역도 실시간으로 보여요.

전부 Cloudflare 위에서 돌아가요. Worker가 앱과 API를 제공하고, **보드마다 하나씩 있는 Durable Object**가 실시간 상태를 들고 있으면서 변경을 전달하고, D1에 사용자·보드·이미지를 저장해요. 전체 코드는 TypeScript 약 5,700줄이고, 에디터 엔진은 React에 의존하지 않아요.

이 글은 만들면서 정말 중요했던 부분들에 대한 이야기예요. 변경이 어떻게 병합되는지, 어디에 저장되는지, 손그림의 떨림이 왜 모든 화면에서 똑같이 보이는지, 그리고 이걸 NixOS에서 돌리려면 무엇이 필요했는지요.

## 보드에 있는 것들

- **도형**: 사각형, 마름모, 원, 선, 화살표, 펜, 텍스트, 스티키 노트, 이미지, 프레임.
- **손그림 스타일**: [roughjs](https://roughjs.com/)를 써요. 거친 정도 슬라이더, 빗금·격자·단색 채우기, 실선·파선·점선을 지원해요.
- **붙는 화살표**: 도형 위에서 화살표를 시작하거나 끝내면 도형이 움직일 때 같이 따라가요. 가운데 점을 끌면 꺾임이 생기고, 곡선으로 바꿀 수도 있어요.
- **정리 도구**: 스마트 가이드, 격자 스냅, 정렬과 분배, 그룹, 잠금, 레이어 순서, 그리고 안에 든 요소와 함께 움직이는 프레임.
- **텍스트**: 도형과 스티키 노트 안에 글을 쓸 수 있고, 한국어도 줄바꿈이 돼요. 글꼴은 손글씨·기본·코드 중에서 고를 수 있어요.
- **수식**: `M`을 누르고 TeX를 입력하거나, `$...$`와 `$$...$$` 텍스트를 붙여 넣으면 돼요.
- **실시간 협업**: 실시간 커서, 선택 영역, 레이저 포인터. 다른 사람의 아바타를 누르면 그 사람이 보고 있는 곳으로 이동해요.
- **공유**: 비공개, 링크로 보기(로그인 불필요), 링크로 편집(로그인 필요). 그 위에 초대 전용 로그인이 있어요.
- 그 밖에 있을 법한 것들: 실행 취소와 다시 실행, 복사와 붙여넣기(이미지 붙여넣기와 드래그 앤 드롭 포함), Alt+드래그 복제, PNG·JSON 내보내기, 다크 모드, 템플릿, 대시보드 썸네일.

## 평평한 요소 하나

보드 위의 모든 것은 같은 타입이에요.

```ts
interface El {
  id: string;
  type: "rectangle" | "ellipse" | "diamond" | "line" | "arrow"
      | "freedraw" | "text" | "sticky" | "image" | "frame";
  x: number; y: number; w: number; h: number;
  strokeColor: string; fillColor: string; roughness: number; /* ... */
  seed: number;     // 도형의 떨림
  version: number;  // 바뀔 때마다 1씩 증가
  nonce: number;    // 무작위 동점 처리용 값
  z: number;        // 그리는 순서
  isDeleted?: boolean;
  // 타입별 선택 필드: text, points, startBind, endBind, assetId, ...
}
```

중첩된 트리도, 타입별 클래스도 없어요. 선택 필드가 있는 레코드 하나뿐이에요. 그룹은 `groupId` 하나로 표현하고, 프레임도 요소이고, 화살표는 id로 도형을 가리켜요. 덕분에 동기화 프로토콜이 아주 작아요. 변경의 단위가 언제나 "요소 X의 새 버전은 이거야"이기 때문이에요. 삭제도 변경이에요. `isDeleted: true`는 다른 편집과 똑같이 동기화되는 삭제 표시(tombstone)예요.

## 병합 규칙

두 사람이 같은 사각형을 동시에 끌고 있어요. 누가 이길까요?

Inkboard는 CRDT도, 연산 변환(OT)도 쓰지 않아요. 각 요소는 버전 번호로 순서를 매기는, 마지막에 쓴 쪽이 이기는(last-writer-wins) 레지스터예요.

```ts
export function shouldReplace(existing: El | undefined, incoming: El): boolean {
  if (!existing) return true;
  if (incoming.version > existing.version) return true;
  if (incoming.version === existing.version && incoming.nonce < existing.nonce) return true;
  return false;
}
```

로컬에서 편집할 때마다 `version`은 이전 버전에 1을 더한 값이 되고, `nonce`는 새로운 무작위 값이 돼요. 버전이 높은 쪽이 이겨요. 두 클라이언트가 같은 요소를 같은 버전으로 올렸다면 nonce가 작은 쪽이 이기고, 양쪽이 똑같은 두 숫자를 비교하니까 **서로 대화하지 않아도 모두가 같은 승자를 골라요**.

핵심은 이 함수가 `shared/types.ts`에 있고, 브라우저와 Durable Object가 둘 다 이걸 가져다 쓴다는 점이에요. "더 새롭다"의 정의가 딱 하나뿐이라서, 서버와 클라이언트가 이 판단에서 서로 어긋날 수가 없어요.

일부러 거칠게 만들었어요. 제가 도형을 옮기는 동안 누군가 색을 바꾸면 둘 중 하나는 사라져요. 단위가 요소 전체이기 때문이에요. 화이트보드라면 이게 맞는 선택이에요. 같은 도형을 같은 순간에 고치는 충돌은 드물고, 진 쪽도 결과를 바로 보게 되고, 규칙은 라이브러리가 아니라 열 줄짜리 함수예요.

## 보드마다 방 하나

보드마다 Durable Object인 `BoardRoom`이 하나씩 있어요. 모든 클라이언트가 여기에 WebSocket을 열고, 이곳이 그 보드의 편집 순서가 정해지는 유일한 장소예요.

```
브라우저 ──ws──▶ Worker ──▶ BoardRoom (보드마다 하나) ──alarm──▶ D1
브라우저 ──ws──┘                │
                                └─ 자체 스토리지: 요소마다 el:<id>
```

Worker는 세션과 보드의 공유 설정을 확인한 다음, 사용자가 누구인지와 편집 권한이 있는지를 함께 소켓을 방에 넘겨요. 방은 **WebSocket hibernation API**로 소켓을 받고, 접속자 정보를 소켓의 attachment에 저장해요. 그래서 한동안 조용한 보드는 아무의 연결도 끊지 않고 메모리에서 내려갈 수 있어요.

`upsert`가 도착하면 방은 각 요소에 `shouldReplace`를 실행해요. 받아들인 요소는 저장하고 나머지 모두에게 전달해요. 거절한 요소에도 답을 해요. 방은 보낸 사람에게 **자기가 진 그 새로운 버전**을 돌려보내요. 그래서 뒤처져 있던 클라이언트는 더 이상 존재하지 않는 상태를 그리는 대신 바로 따라잡아요.

커서, 선택 영역, 레이저 포인터도 같은 소켓으로 오가지만 저장하지는 않아요. 전달하고 나면 잊어버려요.

### 보드를 저장하는 두 곳

D1은 보드 목록, 복사, 썸네일, 읽기 전용 스냅샷을 위해 보드가 머무는 곳이에요. 보드 하나는 행 하나이고, 요소들은 `boards.data`에 JSON 문자열로 들어가요. 포인터가 움직일 때마다 이 행을 쓰는 건 낭비라서, 방은 이렇게 모아서 써요.

1. 받아들인 변경은 **즉시** Durable Object 자체 스토리지에 요소마다 키 하나씩(`el:<id>`) 기록해요.
2. 알람이 걸려 있지 않으면 **2초** 뒤로 알람을 걸어요.
3. 알람이 울리면 살아 있는 요소 전부를 `UPDATE` 한 번으로 D1에 써요.

알람이 울리기 전에 Durable Object가 내려가더라도 잃어버리는 건 없어요. 자체 스토리지에 이미 모든 요소가 있으니까요. 다음에 다시 올라오면 방은 이미 "채워졌다(hydrated)"는 걸 기억하고, 오래됐을 수도 있는 D1 행 대신 자체 스토리지에서 읽어요.

### 클라이언트 쪽

브라우저의 `Sync` 클래스는 100줄이 안 돼요. 로컬 변경은 요소 id를 키로 하는 맵에 모았다가 35ms마다 보내요. 그래서 도형을 화면 끝까지 끌어도 대략 프레임마다 메시지 하나씩, 그것도 각 요소의 최신 버전만 보내요. 소켓이 끊기면 최대 10초까지 지수적으로 간격을 늘리며 다시 연결해요.

오프라인 편집은 병합 규칙에서 자연스럽게 나와요. 연결이 끊긴 동안에도 편집할 때마다 로컬에서 버전이 올라가요. 다시 연결되면 방이 `init` 메시지로 전체 상태를 보내요. 클라이언트는 이걸 `shouldReplace`로 병합한 다음, **자기 사본이 이기는 요소를 전부 다시 보내요**. 따로 오프라인 큐가 없어요. 같은 비교를 반대 방향으로 한 번 더 할 뿐이에요.

## 실행 취소도 그냥 편집이에요

멀티플레이어 에디터에서 실행 취소는 보기보다 까다로워요. 실행 취소가 이전 요소를 그대로 되살리면 버전이 *내려가고*, 다른 클라이언트들은 그걸 오래된 변경으로 보고 거절해요.

그래서 Inkboard의 히스토리는 `before`와 `after` 스냅샷을 저장하고, 실행 취소는 스냅샷을 **새** 편집으로 적용해요.

```ts
const target = dir === "undo" ? (it.before ?? { ...it.after, isDeleted: true }) : it.after;
const next = { ...target, version: Math.max(cur?.version ?? 0, target.version) + 1, nonce: randomSeed() };
```

내용은 과거로 돌아가지만 버전은 앞으로 가요. 그래서 실행 취소는 서버에 있는 무엇과 비교해도 이기고, 다른 사람들에게도 전달돼요. 만들기를 실행 취소하면 삭제가 되고, 다시 실행은 같은 방식으로 요소를 되살려요.

## 모든 떨림은 시드예요

roughjs는 사각형을 살짝 떨리는 선 두 줄로 그리고, 그 떨림은 난수 생성기에서 나와요. 클라이언트마다 각자의 난수를 쓰면 같은 사각형이 화면마다 다르게 보이고, 다시 그릴 때마다 흔들리게 돼요.

해결책이 `seed` 필드예요. 도형을 만들 때 한 번 정해서 요소에 저장하니까 색깔처럼 동기화돼요. 모든 클라이언트가 같은 시드를 roughjs에 넣고 **획 하나하나까지 같은 떨림**을 얻어요.

roughjs로 도형을 만드는 건 싸지 않아서, 렌더러는 요소마다 결과를 캐시해요. 캐시 키는 도형 모양에 영향을 주는 모든 것으로 만들어요. 타입, 크기, 색, 채우기, 선, 거친 정도, 시드, 둥근 모서리, 화살촉이요. 도형을 옮겨도 키는 바뀌지 않으니까 평행 이동과 캐시 적중으로 끝나요. 크기를 바꾸면 새 크기마다 한 번씩 다시 만들어요.

펜으로 그린 선은 [perfect-freehand](https://github.com/steveruizok/perfect-freehand)에 필압 흉내를 켜서 그려요. 마우스 좌표 목록을 잉크처럼 가늘어졌다 굵어지는 채워진 외곽선으로 바꿔 줘요. 점들은 저장하기 전에 단순화해서, 긴 낙서가 거대한 요소가 되지 않게 해요.

## 놓지 않는 화살표

화살표는 붙어 있는 도형의 id를 `startBind`와 `endBind`에 저장해요. 붙어 있는 도형이 움직이면 에디터는 그 도형을 가리키는 화살표들을 찾아서 끝점을 다시 계산해요. 각 끝은 도형의 테두리 위에서, 화살표의 다음 점을 바라보는 지점으로 가요. 화살표가 한 구간뿐이면 반대쪽 도형의 중심을 바라보는 지점으로 가요. 그래서 화살표는 예전 위치를 가리키는 대신 도형을 따라다녀요.

연결은 id일 뿐이라서 id가 바뀔 때는 조심해야 해요. 복사해서 붙여 넣으면 연결을 새 id로 바꿔 줘요. 화살표만 복사하고 붙어 있던 도형은 복사하지 않았다면 연결을 지워요. 그래야 붙여 넣은 화살표가 원래 도형까지 손을 뻗지 않아요.

스마트 가이드는 Figma와 같은 방식이에요. 끄는 동안, 움직이는 상자의 왼쪽·가운데·오른쪽을 화면에 보이는 다른 모든 요소의 왼쪽·가운데·오른쪽과 비교해요(위·가운데·아래도 마찬가지예요). 화면 기준 6픽셀 안에서 가장 가까운 것이 이기고, 상자가 거기에 붙으면서 가이드 선이 그려져요. 이 기준값을 줌 배율로 나누기 때문에 어떤 배율에서든 스냅이 같은 느낌이에요.

## 한국어 텍스트

캔버스에서 줄바꿈은 브라우저가 아니라 직접 해야 하는 일이에요. Inkboard는 문단을 공백 기준으로 나누고, 폭을 재면서 앞에서부터 채워요. 한국어는 보통 어절 사이에 띄어쓰기가 있어서 대부분은 이걸로 충분해요. 긴 URL이나 띄어쓰기 없이 이어진 긴 한글처럼 토큰 하나가 상자보다 넓으면 **글자 단위**로 끊어요. 어차피 한국어는 원래 그렇게 줄이 바뀌기도 하고요.

도형은 라벨에 맞춰 커져요. 원과 마름모는 안쪽 쓸 수 있는 공간이 바운딩 박스보다 작아서, 원은 글 높이의 약 1.42배, 마름모는 약 1.8배가 필요해요.

## 캔버스 위의 수식

수식은 두 번째 커밋에서 추가했는데, 가장 재미있었던 부분이에요. 목표는 LaTeX가 다른 요소와 똑같이 동작하는 거였어요. 옮기고, 크기를 바꾸고, 색을 바꾸고, 내보낼 수 있고, 썸네일에도 나와야 했어요.

과정은 이래요.

1. SVG 출력을 쓰는 **MathJax**가 TeX를 `<svg>`로 바꿔요. `fontCache: "none"` 옵션을 주면 SVG마다 글리프 경로를 자기 안에 담아서, 공유 `<defs>` 없이 혼자서도 그려져요.
2. 그 SVG에 `color="..."`를 붙이고 `data:` URL로 `<img>`에 불러와요. 글리프가 `currentColor`를 쓰니까, 수식 색을 바꾸는 건 캐시 키가 하나 달라지는 것뿐이에요.
3. 그 이미지를 `drawImage`로 캔버스에 그려요. 크기는 MathJax 단위(1em당 1000)에 글자 크기를 곱해서 맞춰요.

MathJax는 약 2.2MB라서, 수식을 쓰지 않는 보드에서까지 받기엔 너무 커요. 그래서 `?url` import와 script 태그로, **보드의 어떤 요소가 처음으로 수식을 필요로 할 때** 불러와요. 도착하기 전까지 수식은 이전 상자 크기를 유지하고, MathJax가 준비되면 캔버스를 다시 그려요. PNG 내보내기와 썸네일은 `img.decode()`를 기다리기 때문에 수식이 빈칸으로 나오지 않아요.

## 누가 들어올 수 있나

로그인은 GitHub나 Google OAuth예요(이름만으로 들어가는 개발용 로그인도 있지만, 프로덕션에서는 절대 켜면 안 돼요). 작은 모임에서 쓰기엔 아무나 가입할 수 있는 게 원하는 것보다 넓어서, `ALLOWED_USERS` 시크릿을 만들었어요.

```sh
npx wrangler secret put ALLOWED_USERS
# me@gmail.com, github:jihoo12, friend@example.com
```

항목은 이메일 주소이거나 `provider:아이디` 형식이에요. 생각보다 중요했던 세부 사항이 몇 가지 있었어요.

- 이메일 항목은 **인증된** 이메일과만 비교해요. GitHub 프로필의 공개 이메일은 인증된 주소라는 보장이 없어서, Inkboard는 API에 인증된 기본 주소를 따로 물어보고, Google은 `email_verified`를 확인해요.
- 초대받지 않은 사용자는 **아무것도 쓰기 전에** 거절해요. 그래서 로그인을 시도해도 데이터베이스에 행이 남지 않아요.
- 이 검사는 로그인할 때만이 아니라 요청마다 실행돼요. 그래서 목록에서 누군가를 빼면 그 사람의 기존 세션도 바로 끊겨요.
- 읽기 전용 링크는 로그인 없이도 열려요. 초대하지 않은 사람에게 보드를 보여 주고 싶을 때 이걸 쓰면 돼요.

세션 토큰은 SHA-256 해시로 저장해요. 그래서 데이터베이스가 새어 나가도 바로 쓸 수 있는 쿠키를 넘겨주게 되지는 않아요.

## NixOS와 실행되지 않던 바이너리

로컬 개발에는 Cloudflare Vite 플러그인을 쓰는데, 이 플러그인은 실제 `workerd` 런타임을 돌려요. npm은 일반 리눅스용으로 미리 빌드된 `workerd`를 받아 오는데, NixOS에서는 이게 실행되지 않아요. 불러올 `/lib64/ld-linux-x86-64.so.2`가 없거든요.

해결책은 짧은 `postinstall` 스크립트예요. NixOS에서만, 실행되지 않는 `workerd` 바이너리를 찾아서 `patchelf`로 nixpkgs의 glibc를 쓰도록 고쳐요.

```sh
GLIBC="$(nix eval --raw nixpkgs#glibc.outPath)"
nix shell nixpkgs#patchelf -c patchelf \
  --set-interpreter "$GLIBC/lib/ld-linux-x86-64.so.2" \
  --set-rpath "$GLIBC/lib" "$B"
```

다른 시스템에서는 바로 끝나고, 이미 실행되는 바이너리는 건너뛰기 때문에 `npm install`을 다시 해도 괜찮아요. 우아하진 않지만, 덕분에 `npm install && npm run dev`가 제 컴퓨터에서도 다른 곳과 똑같이 돌아가요.

## 한계

- 이미지는 D1에 BLOB으로 저장해요. 브라우저에서 먼저 최대 1600px로 줄이고 WebP로 다시 인코딩해서, 한 장에 약 1.9MB까지예요. 이미지를 많이 쓴다면 R2로 옮기는 게 맞아요.
- 보드 하나가 D1의 JSON 행 하나라서, 아주 큰 보드(수 MB)는 한계에 부딪혀요.
- 아직 도형을 회전할 수 없어요.
- 병합이 요소 단위라서, 두 사람이 같은 도형의 서로 다른 속성을 같은 순간에 고치면 하나만 남아요.

## 다시 만든다면

다시 만들어도 그대로 할 건 공유하는 병합 규칙이에요. "어느 버전이 더 새로운가"가 양쪽에서 가져다 쓰는 함수 하나가 되자, 나머지는 거기서 따라 나왔어요. 오프라인 편집, 실행 취소, 충돌 응답, 재연결이 전부 같은 비교를 다른 자리에서 쓰는 것뿐이에요. 보드마다 있는 Durable Object가 그 비교를 실행할 단 하나의 장소가 되어 주고, D1은 결국에만 최신이면 돼요.

가장 먼저 바꿀 건 저장 방식이에요. 보드마다 JSON 행 하나는 시작하기에 가장 빠른 방법이었고, 보드가 커지면 가장 먼저 깨질 곳이기도 해요.
